# 온라인 시연 기록 설정 (v0.7.0)

## Supabase에서 한 번 실행

1. fanplay-demo 프로젝트 왼쪽 **SQL Editor** → **New query**.
2. `supabase/migrations/2026111801_demo_records.sql` 전체를 복사해 붙여넣고 **Run**.
3. 성공 후 아래 읽기 전용 확인문을 실행하면 ready=true, version=1이 반환된다.

```sql
select public.fanplay_demo_status();
```

공개용 키로는 테이블이나 함수를 만들 수 없다. 프로젝트 소유자가 이 설정을 실행해야 한다. SQL은 기존 테이블·기록을 삭제하지 않으며 재실행할 수 있다. DB 비밀번호와 관리자 키는 앱에 필요하지 않다.

## 저장 방식

- 입력한 아이디를 소문자로 변환한다. 소문자·숫자·밑줄 3~24자만 사용한다.
- 같은 아이디는 같은 과제용 공유 기록이다. 아이디를 아는 누구나 조회·수정할 수 있다. 본인 인증·개인 계정 기능이 아니다.
- 개인정보·개인 사진을 넣지 않는다. 비밀번호와 이메일은 수집하지 않는다.
- 테이블은 fanplay_private 스키마에 두고 직접 접근 권한을 부여하지 않는다. 공개 함수는 상태 확인, 지정 ID 한 개 열기, 버전이 일치하는 지정 ID 한 개 저장만 제공한다. 전역 목록·삭제·임의 SQL 함수는 제공하지 않는다. 아이디의 비밀성이나 개인 데이터 보호를 보장하지는 않는다.
- JSON 상태는 5MB로 제한한다. 기록은 초기화하지 않고 기존 상태에서 업데이트한다. 저장 버전이 달라진 요청은 409 오류로 거절한다.
- 기록 삭제가 필요하면 프로젝트 소유자가 DB에서 해당 행을 삭제한다.
- localStorage의 기존 기록은 유지한다. 온라인 아이디를 열면 마이페이지에서 기기 기록 가져오기를 선택할 수 있다.
- 세션 토큰 없이 마지막 사용 아이디만 해당 브라우저에 기억한다. 페이지 재접속 시 최신 온라인 기록을 읽는다. 사용 종료는 로컬 기록으로 돌아간다.
- 같은 아이디의 다른 기기 변경을 실시간 구독하지 않는다. 저장 충돌 시 내려받기로 기록을 보관한 뒤 '온라인 기록 다시 불러오기'를 사용한다.
- 로컬 Node 서버는 기존 비밀번호 계정으로 동작한다. GitHub Pages 또는 일반 정적 서버에서 온라인 시연 아이디를 사용한다.

## 검증

SQL 함수를 테스트 PostgreSQL 환경에서 검사한다. 아이디 입력, 생성/조회, 저장 버전 증가, 충돌, 크기/형식 제한, 직접 테이블 접근 거절, 재실행 보존을 확인한다.
브라우저에서 서로 다른 프로필이 같은 아이디를 열어 이어가는 흐름과 저장 실패 시 기존 상태 보존, 재시도, 로컬 기록 유지, 마이페이지 안내를 확인한다. 모의 서버 검증은 실제 Supabase 연결 검증과 별개로 기록한다.

2026-11-18: PGlite 0.5.16의 PostgreSQL 엔진과 Edge를 사용해 tests/cloud-demo.cjs 통과. 이후 프로젝트 소유자가 설정문을 실행했으며 실제 상태 요청 ready=true, version=1을 확인했다. 실제 Supabase에 테스트용 아이디로 기록을 생성하고 두 브라우저에서 티켓·선수 동기화, 저장 버전 충돌 거절, 온라인 기록 재조회, 재접속 복원, 선택 저장, 사용 종료를 검증했다. 테스트 행은 qa_ 접두사로 구분되며 프로젝트 소유자가 필요 시 삭제할 수 있다.

```text
PGLITE_MODULE: @electric-sql/pglite 설치 경로 (또는 패키지 해석 가능한 환경)
PLAYWRIGHT_MODULE: playwright 설치 경로
BROWSER_EXECUTABLE: 테스트할 Chromium 브라우저 실행 파일 (미지정 시 Playwright 기본)
node tests/cloud-demo.cjs
```

무료 프로젝트의 정지·사용량 정책은 Supabase 정책에 따른다. 이 구성은 과제용이며 비공개 개인 계정이 필요하면 Supabase Auth 및 사용자별 접근 규칙으로 변경한다.
