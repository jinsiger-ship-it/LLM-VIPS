# 버전 관리와 복구

현재 버전은 저장소 루트 VERSION으로 확인한다. 화면의 버전과 JS/CSS의 캐시 버전도 함께 갱신한다.

- main: 검증한 공개 배포 소스.
- v0.5.1: 이번 통합 전 공개본 보관 태그.
- v0.6.0: 압축형 후보 카드와 이야기·장식 통합본.
- v0.7.0: Supabase 온라인 시연 아이디·기기 간 이어하기·저장 충돌 처리. 비밀번호 없는 공유 기록이며 기존 로컬 비밀번호 계정과 별개.
- CHANGELOG.md: 사용자에게 영향을 주는 변경과 저장 호환성 기록.
- GitHub Pages 배포 전 Node 테스트를 실행한다. 브라우저 검사는 별도로 실행하며 배포 후 공개 경로도 확인한다.

## 변경 기준

기존 README의 v0.x 체계를 이어간다. 기능 추가는 0.x.0, 동작을 유지하는 오류 수정은 0.x.y로 올린다. 버전 태그는 다시 쓰지 않는다. 작업은 기능 브랜치에서 진행하고 검증한 결과를 main에 반영하는 방식을 권장한다.

## 이전 버전 확인

별도 폴더에 복제한 뒤 `git switch --detach v0.5.1` 또는 `git switch --detach v0.6.0`으로 확인한다. 기존 작업 폴더의 미저장 변경을 먼저 보존한다. 공개본 복구는 해당 변경의 되돌리기 커밋을 만들어 main에 반영한다. 강제 푸시로 이력을 지우지 않는다.

앱 소스 복구와 사용자 데이터 복구는 별개다. 구버전 앱은 새로운 저장 규칙을 읽지 못할 수 있으므로 공개 롤백 전 최신 브라우저 기록을 내보내거나 별도 사본으로 보관한다. database 폴더와 계정 DB는 공개 파일에 포함하지 않는다.

## 통합 판단

GitHub의 후보 생성은 같은 총합 안에서 서로 다른 시작을 제공한다. 요청한 1안은 후보 세 명을 세로로 배치해 각 항목을 같은 위치에서 비교하게 한다. 시작 성향은 선택을 돕는 설명이며 은퇴 호칭은 실제 플레이에서 결정한다.

게임의 장식 보상을 관람 티켓 꾸미기와 연결해 게임과 기록 기능을 함께 사용할 이유를 만든다. 큰 인벤토리는 제거하고 필요한 꾸미기 화면에서 보여준다. 기록과 상세 능력치를 접어서 현재 장면과 선택에 집중하도록 했다.

이는 첫 사용의 부담을 낮추고 반복 플레이의 동기를 만들려는 설계 가설이다. 시장 성공을 검증한 결과는 아니다. 부차적인 기능을 필요할 때 보여주는 접근은 [Nielsen Norman Group의 progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) 원칙을 참고했다. 향후 첫 경기 시작률, 첫 은퇴 도달률, 두 번째 커리어 시작률, 장식 적용률로 검증한다. 이번 버전에는 사용자 추적 코드를 추가하지 않았다.
