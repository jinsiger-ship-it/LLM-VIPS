# 개발 방향과 범위

기록일: 2026-11-06 (한국 시간 기준). 사용자 요구: 지정한 VS Code 프로젝트를 첨부 계획서에 맞춰 제작하고, 방향과 작업 내용을 세세하게 기록.

## 근거와 차이

첨부 문서는 2026-11-03 검토, 2026-11-06 정리된 과거 ZIP 검토 보관본이다. 원본 ZIP, 9주차 기획서 전문, GitHub 저장소와 과제 안내문은 이번 작업에 제공되지 않았다. 따라서 문서 속 기존 기능을 현재 파일의 검증된 상태로 취급하지 않았다.

실제 지정 폴더에는 index.html, app.js, style.css, README.md, 11.03_test.html이 있었다. index의 제목과 README는 Diamond Memories였으며, app.js는 diamond-v1 키, 감독의 5개 선택, night/gold/trophy 보상을 사용했다. 첨부 문서의 FANPLAY 8시즌 버전과 다른 출발점이었다.

이번 결정은 첨부 문서를 목표 사양으로 사용하여 FANPLAY의 8시즌 선수 커리어로 확장하는 것이다. 기존 감독 게임은 백업 대상으로 두고 새 실행 진입점은 index.html 하나로 정했다. 별도 11.03_test.html은 변경하지 않는다. sources 참고 자료는 수정하지 않는다.

## 중심 경험

티켓 제작 → 커리어 8시즌 완주 → 별과 결말 보상·칭호 획득 → 수집함에서 티켓 수정 → 획득 프레임·스티커 적용 → 저장 → 새로고침으로 보상과 디자인 복원.

## 우선순위와 구현 판단

1. 보상 연결: 프레임 2종, 스티커 2종, 칭호 3종을 ID 기반으로 관리한다. 중복 지급을 막고 새 선수 생성 시 유지한다.
2. 저장 일관성: 전역 데이터를 직접 변경하지 않고 트랜잭션 사본을 먼저 저장한다. 실패 시 이전 메모리와 저장소 유지, 오류 메시지 표시.
3. 대표와 칭호: 사용자가 직접 선택하며 대표 티켓 삭제 시 참조를 해제한다.
4. 선택 인과: 각 선택의 증감, 직전 결과와 전체 로그를 공개한다. 투수와 야수 문구를 나누고 6시즌에는 능력치에 따른 보충 문구를 둔다.
5. 관리 가능성: 콘텐츠·저장·게임·티켓·UI를 파일로 분리한다. 모든 동작을 한 줄 파일로 압축하지 않고 역할 주석을 둔다. UI 템플릿은 함수 단위이며 향후 작은 컴포넌트로 더 분리할 수 있다.

## 디자인 방향

야구 기념 티켓과 클럽하우스를 모티프로 크림 종이 바탕, 포레스트 그린, 작은 영문 분류, 큰 한글 타이포를 사용한다. 사진이 없어도 다이아몬드 그래픽과 바코드로 티켓의 형태를 유지한다. 응원팀 변경은 앱 강조색에 적용하며 티켓에 고른 컬러는 독립적으로 남긴다. PC에서는 좌우 작성·미리보기, 모바일에서는 세로 흐름과 가로 스크롤 메뉴를 사용한다. 720px·1050px 분기, 키보드 포커스, 상태 알림, 모션 감소 설정을 반영한다.

## 제외 범위와 사람의 판단

서버, 인증, 경기 API, 실시간 생성형 AI, 외부 공개 배포, 실제 커뮤니티를 이번 범위에 넣지 않았다. 제공 문서도 서버 없이 핵심 연결을 먼저 검증하도록 권장했다. 감독→선수 게임 변경의 과제 적합성은 안내문을 받지 못해 판단하지 않았다. 게임 문구·아이템 명·결말 기준은 이번 제작에서 정한 예시 값이며 팀의 최종 합의로 확정된 사실이 아니다.
