# FANPLAY — 나만의 야구를 수집하다

2026-11-06 제작. 첨부한 상세 검토·개발 계획을 바탕으로, 기존 Diamond Memories 로컬 프로젝트를 선수 커리어형 FANPLAY로 확장한 정적 웹앱입니다.

## 실행

VS Code에서 이 폴더를 열고 `index.html`을 브라우저로 여세요. 또는 Live Server로 실행하세요. Python이 있다면 이 폴더에서 `python -m http.server 8000` 실행 후 `http://localhost:8000`에 접속할 수 있습니다. Node/npm 설치나 API 키는 앱 실행에 필요하지 않습니다. 정적 서버 방식이 권장됩니다.

## 구현

- 티켓: 경기 기록 → 꾸미기 → 미리보기 → 저장. 클래식·전광판·포토 / 4색 / 태그 / 사진 / 프레임·스티커.
- 수집함: 전체·직관·중계 필터, 상세 및 수정, 삭제, 대표 지정, 로컬 게시.
- 선수 커리어: 4개 포지션, 8시즌, 시즌마다 3선택, 능력치와 로그 저장, 3결말.
- 연결: 완주 별 + 결말 고유 보상 + 칭호 → 인벤토리 → 티켓 적용 → 저장·복원.
- 프로필: 닉네임, 10개 구단 테마, 대표 티켓, 칭호, 보상·활동 수와 최근 활동.
- 커뮤니티: 로컬 게시 사본, 좋아요 토글, 댓글, 게시글 삭제. 실제 온라인 공유 아님.
- 저장: 사본 저장 후 메모리 교체, v2 필드 정규화, 기존 키 유지 및 diamond-v1 읽기.

## 시연 순서

1. 티켓을 만들고 수집함에 저장합니다.
2. 커리어 게임에서 선수 이름과 포지션을 정하고 8번 선택합니다.
3. 마이페이지에서 보상과 칭호를 확인합니다.
4. 수집함의 ‘상세 / 수정’ → 꾸미기에서 보상을 적용하고 저장합니다.
5. 대표 지정 및 칭호 전시 후 새로고침합니다.

## 검사

`node tests/integration.cjs` 및 `node tests/screens.cjs`로 재현합니다. 실제 결과와 미검증 항목은 [검사 기록](docs/test-checklist.md)에 구분했습니다. 화면 렌더 함수 검사는 실제 브라우저 검수가 아닙니다.

## 한계

로그인·서버·실시간 경기 API·실시간 AI·다른 사용자와 공유하는 커뮤니티가 없습니다. 데이터는 브라우저 및 접속 주소별 localStorage에 남습니다. 파일 실행, localhost 포트 변경, 브라우저 변경 간 데이터는 자동 이동하지 않습니다. 기존 저장소는 삭제하지 않습니다. 새 데이터는 `fanplay-prototype-v1` 키에 schemaVersion 2로 저장됩니다. 사진 누적 시 저장 공간이 부족할 수 있습니다. Google Fonts만 네트워크에서 불러오며 실패하면 시스템 글꼴을 사용합니다.

첨부 문서의 `LLM-VIPS-main.zip`은 이 작업에 제공되지 않았으므로 해당 원본과의 완전 호환·기능 동일성은 보장하지 않습니다. 실제 선수 통계와 무관한 창작 게임이며 선택에 따른 다음 시즌은 대부분 고정입니다. 과제 요구사항 적합성과 실제 사용자 사용성은 담당자가 확인해야 합니다. GitHub Pages 배포나 실제 사용자 테스트는 수행하지 않았습니다.
