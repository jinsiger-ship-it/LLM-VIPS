# 모바일 브라우저 개선 기록

작업일: 2026-11-06. 사용자가 모바일 사용 예정이라고 알린 뒤 ‘브라우저’라고 사용 환경을 확정했다. 설치형 네이티브 앱이나 앱스토어 배포가 아닌 반응형 웹으로 개선했다.

## 방향과 실제 수정

1. 상단 가로 스크롤 메뉴를 휴대전화 화면에서는 6칸 하단 고정 메뉴로 바꿨다. 홈·만들기·수집함·게임·커뮤니티·마이 메뉴를 한 번의 탭으로 연다. 아이콘은 장식이며 글자 라벨과 aria-current를 유지한다.
2. 720px 이하에만 css/mobile.css를 적용한다. PC용 기본 스타일과 기능은 유지한다. 360px 이하에는 제목·점수·인벤토리 밀도를 추가로 조정한다.
3. 하단 메뉴, 알림, 본문에 safe-area-inset 여백을 반영하고 viewport-fit=cover를 추가했다. 홈 인디케이터에 버튼이 겹치는 것을 줄이려는 조치이며 실제 아이폰 검수는 별도다.
4. 일반 버튼은 최소 46px, 메뉴·수집함 작업 버튼은 44px 이상, 게임 선택은 74px 이상 높이로 설정했다. 작은 수정·삭제 버튼도 2열로 나눴다.
5. 입력·선택·감상 글자 크기를 16px로 설정했다. 휴대전화에서 읽기와 입력을 쉽게 하고 일부 모바일 브라우저의 입력 확대를 줄이려는 목적이다. 화면 확대 기능을 막지는 않는다.
6. 티켓 작성 화면에서 큰 미리보기가 폼보다 먼저 나오던 순서를 바꿔 입력 폼 뒤에 미리보기를 배치했다. 입력→꾸미기→최종 확인 흐름을 유지한다. 단계 표시는 상단에 붙도록 했다.
7. 수집함 필터는 3열, 작업은 2열로 구성했다. 댓글 입력 폭, 긴 팀명과 감상, 좁은 화면의 점수·바코드 영역을 조정했다.
8. 저장 알림은 하단 메뉴 위에 표시한다. 프로필의 선택 칭호가 기존 모바일 규칙에 의해 숨겨지지 않도록 했다.

## 파일별 변경

- index.html: viewport-fit=cover, mobile.css 로드, 장식 아이콘과 짧은 메뉴 라벨.
- css/mobile.css: 모바일 전용 반응형·터치·안전 여백 규칙.
- README.md: 모바일 사용·실제 접속 방법 및 이 기록 링크.
- docs/development-log.md / test-checklist.md: 후속 작업과 확인 범위 추가.

## 검사와 한계

기존 로직·화면 렌더 검사로 기능 회귀를 확인한다. 검사 통과는 실제 휴대전화의 레이아웃, 키보드, 사진 선택, 안전 여백을 확인했다는 뜻이 아니다. 기존 브라우저 미리보기 연결·소켓 제한은 해결되지 않았으며 실제 iOS Safari·Android Chrome 검수는 미수행이다. 앱 내부 로직·저장 키·기존 데이터·보상 규칙은 변경하지 않았다.

## 휴대전화에서 여는 방법

PC의 C: 경로 링크는 휴대전화에서 직접 열 수 없다. PC와 휴대전화를 같은 Wi-Fi에 연결하고 VS Code Live Server 등으로 정적 서버를 연 뒤, 휴대전화에서 PC의 로컬 IP와 포트로 접속한다(예: http://192.168.0.10:5500). 예시 IP는 실제 PC 주소가 아니며 방화벽·학교/공유기 네트워크 정책에 따라 접근이 제한될 수 있다. 방화벽 설정은 이번 작업에서 변경하지 않았다. 안정적으로 같은 주소를 유지해야 동일한 localStorage 데이터를 다시 볼 수 있다. 외부 어디서든 접속하려면 별도 웹 배포가 필요하며 이번 작업에서는 공개하지 않았다.
