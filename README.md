
# FANPLAY

**[FANPLAY 모바일 바로가기](https://jinsiger-ship-it.github.io/LLM-VIPS/)**

야구 관람 티켓을 만들고 수집하며 선수 커리어 게임을 즐기는 모바일 웹앱입니다. GitHub Pages에서 만든 기록은 브라우저에 저장됩니다.

같은 브라우저의 이전 FANPLAY 기록은 첫 실행에 읽어옵니다. 이후 메인과 보관본의 기록은 별도로 저장됩니다.

## 파일 구성

- `index.html` · 모바일 사이트 진입점
- `pages/`, `js/`, `css/` · 보관 화면, JavaScript, 스타일
- `docs/`, `tests/` · 개발 문서와 자동 검사
- `data/kbo/` · 추후 KBO 기록 파일을 둘 자리
- `database/` · 로컬 계정 데이터베이스 위치와 운영 안내

## 로컬 계정 실행

Node.js 24 이상으로 저장소 폴더에서 `node server.cjs`를 실행합니다. [로컬 마이페이지](http://127.0.0.1:8080/#profile)에서 회원가입과 로그인을 사용할 수 있습니다. 비회원 기록은 브라우저에, 로그인 후 저장한 티켓과 게임 기록은 로컬 SQLite DB에 보관합니다.

`node tests/integration.cjs`, `node tests/screens.cjs`, `node tests/accounts.cjs`로 검사할 수 있습니다. 실제 SQLite 파일은 Git과 Pages 배포 대상에서 제외됩니다. [DB 안내](database/README.md)

### 3.2 서비스 정의

FANPLAY는 야구 팬이 기억에 남는 경기를 기념 티켓으로 제작하고 수집할 수 있는 서비스입니다.

직접 경기장을 방문한 경우뿐만 아니라 중계로 관람한 경기 역시 기록할 수 있습니다.

또한 선수 커리어 게임을 통해 보상을 획득하고 이를 티켓 꾸미기에 활용하는 경험을 제공합니다.

실제 야구 경기 예매 및 입장권 발권을 목적으로 하지 않습니다.

### 3.3 핵심 기능

#### 기능 1 — 티켓 제작

- 경기 정보 입력
- 관람 방식 선택
- 티켓 디자인 선택
- 사진 첨부(선택)
- 꾸미기 아이템 적용
- 티켓 미리보기
- 티켓 저장

#### 기능 2 — 티켓 수집함

- 제작한 티켓 목록 조회
- 직관/중계 관람 구분
- 티켓 상세 확인
- 티켓 수정 및 삭제
- 대표 티켓 설정

#### 기능 3 — 선수 커리어 게임

- 선수 및 포지션 선택
- 시즌별 선택지 진행
- 선택에 따른 능력치와 결과 기록
- 커리어 결과 확인
- 보상 및 칭호 획득
- 티켓 꾸미기 기능과 연결

- 티켓 게시
- 게시글 조회

#### 기능 5 — 마이페이지

### 3.5 KBO 경기 데이터 연동

#### 목적

티켓을 제작할 때 사용자가 직접 경기 정보를 모두 입력하는 과정을 줄이고, 실제 KBO 경기 데이터를 활용할 수 있도록 합니다.

#### 요구 기능

| ID | 요구사항 | 상태 |
|---|---|---|
| KBO-01 | KBO 경기 데이터를 JSON 형태로 준비하거나 불러오기 | 예정 |
| KBO-02 | 날짜 입력 또는 선택 | 예정 |
| KBO-03 | 경기장 입력 또는 선택 | 예정 |
| KBO-04 | 날짜와 경기장 조건으로 데이터 조회 | 예정 |
| KBO-05 | 해당 경기 정보 화면 표시 | 예정 |

#### 목표 사용 흐름

```text
티켓 제작 진입
      |
      v
날짜 선택
      |
      v
경기장 선택
      |
      v
KBO JSON 데이터 조회
      |
      v
해당 경기 정보 표시
      |
      v
티켓 꾸미기
      |
      v
티켓 저장
```

#### 데이터 구조

**확인 필요:** KBO 데이터 구조는 아직 최종 확정되지 않았습니다.

현재 요구사항에 명시된 조회 조건은 날짜와 경기장입니다.

조회 결과에 포함할 팀명, 경기 결과, 경기 시간 등의 세부 필드는 실제 데이터 구조를 확인한 뒤 확정해야 합니다.

#### 데이터 관리

- 데이터 보관 후보 위치: `data/kbo/`
- 데이터 형식: JSON
- 데이터 출처: KBO 경기 기록
- 갱신 주기: 미정
- 수집 방식: 미정

### 3.6 데이터 저장 요구사항

기존 README 기준 데이터 저장 방식은 다음과 같습니다.

| 환경 | 저장 방식 |

향후 기능 수정 시 다음 항목을 확인합니다.

- [ ] 하단 메뉴가 5개로 표시되는가?
- [ ] 메뉴 순서가 커뮤니티, 수집함, 홈, 게임, 마이페이지인가?
- [ ] 하단 만들기 버튼이 제거되었는가?
- [ ] 홈에서 티켓 제작 기능에 접근할 수 있는가?
- [ ] 날짜를 선택할 수 있는가?
- [ ] 경기장을 선택할 수 있는가?
- [ ] JSON에서 해당 경기 정보를 조회할 수 있는가?
- [ ] 조회 결과를 티켓 제작에 활용할 수 있는가?
- [ ] 기존 수집함 및 게임 기능이 유지되는가?
- [ ] 모바일 화면에서 정상적으로 표시되는가?

위 체크리스트는 향후 검증용이며 현재 모든 항목이 구현되었다는 의미는 아닙니다.

### 3.8 미확정 사항

- KBO 경기 데이터 수집 방식
- KBO JSON 데이터 필드 및 구조
- 경기 데이터 갱신 주기
- 검색 결과가 없을 때의 처리
- 취소 및 예정 경기의 처리
- 커뮤니티 온라인 연동 여부
- 향후 버전 번호 및 배포 일정
- 실제 모바일 기기 테스트 결과
